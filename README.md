# Входная практика по Linux

Команда использует служебный скрипт: он читает название приложения из файла настроек и каждые две секунды пишет сообщение в лог. Подготовь его к запуску, измени настройку и покажи, как проверить и остановить процесс.

Практика рассчитана максимум на 2 часа. Изучение теории, установка окружения и получение файлов задания в это время не входят. Git используется только для получения файлов и не проверяется.

## Подготовка

Работай обычным пользователем в Linux. На Windows подойдёт WSL или виртуальная машина с Linux, на macOS - виртуальная машина с Linux.

В терминале Linux выполни:

```bash
git clone https://github.com/haleecolemax2uk/testovoe_zadanie_devops.git linux-entry-practice
cd linux-entry-practice
```

До начала отсчёта времени проверь, что доступны Git, Bash и команды `pwd`, `ls`, `cd`, `cat`, `tail`, `ps`, `chmod`, `kill`. При проблемах с подготовкой обратись к ментору.

## Файлы задания

| Файл | Назначение |
| --- | --- |
| `start.sh` | Готовый скрипт. Изначально у него нет права на запуск. Переписывать код не нужно. |
| `config/app.conf` | Настройка `APP_NAME` в формате `APP_NAME=название`, без пробелов вокруг `=` и без кавычек. |
| `logs/app.log` | Лог, который появится после запуска. Новые сообщения добавляются в конец. |
| `results.txt` | Шаблон для команд и результатов проверки. |

## Задание

1. Через терминал открой каталог задания, определи его полный путь и посмотри содержимое README.md, start.sh и config/app.conf.
2. Измени `APP_NAME` на `devops-test`. Для редактирования можно использовать удобный текстовый редактор.
3. Посмотри права на `start.sh`. Дай владельцу право на запуск, не открывая запись всем пользователям.
4. Запусти скрипт в фоновом режиме из каталога задания:

   ```bash
   ./start.sh &
   ```

5. Посмотри последние 10 строк `logs/app.log`. Убедись, что новые сообщения содержат `app=devops-test`.
6. Найди PID своего скрипта с помощью `ps`. Останови именно этот процесс командой `kill` и проверь, что он завершился.
7. Заполни `results.txt`: запиши команды, результаты и возникшие трудности.

Скрипт читает настройки при запуске. Чтобы применить новое значение после изменения файла, останови свой процесс и запусти скрипт снова. Не запускай несколько копий одновременно.

## Что должно получиться

- В настройках и новых строках лога указано `devops-test`.
- Владелец может запускать `start.sh`; запись в файл не открыта всем пользователям.
- Ты нашёл запущенный процесс и остановил его.
- В `results.txt` есть команды и результаты, которые ты можешь объяснить.

## Как сдавать

Пришли ментору заполненный `results.txt` и файл `config/app.conf`. В results.txt включи несколько строк лога и вывод команды проверки прав. Коммиты, push и merge request не требуются. Сохрани рабочий каталог до созвона, чтобы показать файлы и повторить действия в терминале.

Если за 2 часа не закончил, пришли текущий results.txt: что получилось, где остановился, текст ошибки и что уже проверил.

## Проверка стартовых файлов для ментора

Тесты не входят в задание ученика. Для проверки скрипта в отдельной временной копии нужен Python 3:

```bash
python3 -m unittest discover -s tests -v
```

Перед выдачей проверь сценарий на используемом Linux-окружении. Клонирование должно сохранять отсутствие права на запуск у `start.sh`; это часть практики.
